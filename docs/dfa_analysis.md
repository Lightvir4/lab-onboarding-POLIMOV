# Анализ потоков данных

Исходный фрагмент анализируется как функция `process_transaction`.

| Переменная | Точки определения (Def) | Точки использования (Use) |
|---|---|---|
| `log_entry` | строка 2; строка 10 | строка 13 в `file.write` |
| `status` | строка 5, только при `amount > 0` | строка 10 в конкатенации; строка 15 при возврате |
| `balance` | строка 6, только при `amount > 0` | строка 7 при вычислении `new_balance` |
| `new_balance` | строка 7 | строка 8 в `update_balance` |
| `file` | строка 12 | строка 13 в `file.write`; закрытия нет |

## Дефекты, найденные DFA

1. **Неинициализированная переменная.** При `amount <= 0` ветвь с `status = "approved"` не выполняется, но `status` используется в строке формирования журнала и в `return`. Результат - `UnboundLocalError`.
2. **Мёртвое присваивание.** Значение `log_entry = "Start processing"` перезаписывается до первого чтения, поэтому не влияет на результат.
3. **Утечка ресурса.** Объект файла открыт через `open`, однако `file.close()` не вызывается. При ошибке или большом числе вызовов это может исчерпать файловые дескрипторы.

Исправленная версия находится в `src/fixed_transaction.py`: статус имеет начальное значение, журнал создаётся единожды и файл закрывается контекстным менеджером.
