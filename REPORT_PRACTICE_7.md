## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек
Ниже приведен анализ точек определения (Def) и использования (Use) переменных для исходного фрагмента кода функции `process_transaction`:

| Переменная | Строка Def (Определение) | Строка Use (Использование) |
| :--- | :--- | :--- |
| **log_entry** | Строка 2 (`log_entry = "Start processing"`) | Нет использования (перезаписывается на строке 10) |
| | Строка 10 (`log_entry = "Transaction finished..."`) | Строка 13 (`file.write(log_entry)`) |
| **status** | Строка 5 (`status = "approved"`) | Строка 10 (конкатенация), Строка 15 (`return status`) |
| **balance** | Строка 6 (`balance = get_balance(user_id)`) | Строка 7 (`balance - amount`) |
| **new_balance** | Строка 7 (`new_balance = balance - amount`) | Строка 8 (`update_balance(user_id, new_balance)`) |
| **file** | Строка 12 (`file = open("audit_log.txt", "w")`) | Строка 13 (`file.write(log_entry)`) |

### 1.2. Описание выявленных дефектов
*   **Дефект 1 (Неинициализированная переменная):** Возникает на строке 10 при условии, что `amount <= 0`. В этом случае блок `if` не выполняется, переменная `status` не инициализируется, что приводит к критической ошибке `UnboundLocalError: local variable 'status' referenced before assignment`.
*   **Дефект 2 (Мертвое присваивание / Dead Store):** На строке 2 переменной `log_entry` присваивается значение `"Start processing"`. Однако это значение нигде не читается и полностью перезаписывается на строке 10.
*   **Дефект 3 (Утечка ресурса / Resource Leak):** На строке 12 открывается дескриптор файла `open("audit_log.txt", "w")`, но метод `file.close()` отсутствует. В случае системных сбоев или долгой работы программы это приводит к утечке системных ресурсов.

## 2. Дизассемблирование

### 2.1. Восстановленный код на языке Python
Ассемблерный код реализует цикл подсчета суммы чисел от 1 до 10 включительно. Эквивалентный код на Python:

```python
total_sum = 0
for i in range(1, 11):
    total_sum += i
```

### 2.2. Краткое пояснение логики работы ассемблерного фрагмента
*   `movl $0, -4(%rbp)` и `movl $1, -8(%rbp)` инициализируют переменные в стеке: аккумулятор (сумма) = 0, счетчик = 1.
*   Инструкция `jmp .L2` выполняет безусловный переход к проверке условия цикла.
*   В блоке `.L2` команда `cmpl $10, -8(%rbp)` сравнивает значение счетчика с числом 10.
*   Инструкция `jle .L3` (jump if less or equal) перенаправляет выполнение в тело цикла `.L3`, если счетчик меньше или равен 10.
*   В теле цикла `.L3` значение счетчика прибавляется к аккумулятору (`addl %eax, -4(%rbp)`), после чего счетчик инкрементируется на 1 (`addl $1, -8(%rbp)`).
*   После выхода из цикла итоговый результат помещается в регистр возврата `%eax`.

## 3. Деобфускация

### 3.1. Расшифрованная строка
После декодирования строки из Base64 получается следующий код:
```python
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы
Выполнение данного скрипта представляет **критическую угроzen безопасность**. Команда `rm -rf /` в Unix-подобных операционных системах запускает рекурсивное (`-r`) принудительное (`-f`) удаление всех файлов и каталогов, начиная от корневого каталога (`/`). Запуск этой команды от имени администратора (root) приводит к полному уничтожению операционной системы и потере всех данных на сервере или рабочей машине.

### 3.3. Методы защиты
1.  **Запрет использования опасных функций:** Полный отказ от использования встроенной функции `exec()` и `eval()` для выполнения динамического или невалидированного кода.
2.  **Статический анализ кода:** Применение автоматизированных инструментов (например, Bandit для Python), которые на этапе CI/CD подсвечивают использование `exec` и опасных модулей наподобие `os.system`.
3.  **Принцип наименьших привилегий:** Запуск приложений в изолированных контейнерах (Docker) с ограниченными правами пользователя (non-root), что локализует и минимизирует ущерб в случае выполнения вредоносного кода.

## 4. Настройка и прохождение линтера

### 4.1. Описание настроенных правил в файле .flake8
В конфигурационном файле `.flake8` заданы следующие параметры:
*   `max-line-length = 80`: Ограничение максимальной длины строки кода до 80 символов для удобочитаемости.
*   `extend-ignore = E203, W503`: Исключение конфликтов форматирования (пробелы перед двоеточием и переносы строк перед бинарными операторами) для совместимости с автоматическими форматировщиками (например, Black).
*   `exclude = .git,__pycache__,docs`: Директивы игнорирования служебных директорий, кэша и документации, анализ которых не требуется.
